# 0.9.0 功能完善与验收

## 已实现

| 范围 | 当前行为 |
| --- | --- |
| 多作品流水线 | 扫描、生成、发送分别公平调度；慢模型不阻塞扫描。云模型并发1～4可设，默认2；同一本地模型服务串行。发送始终串行并至少间隔3秒 |
| 多账号 | 独立账号槽位与加密令牌，作品绑定账号；后台使用绑定账号而非当前选中账号，冷却按账号独立，发送总调度仍串行 |
| 积压策略 | 每作品最长等待、积压阈值、暂停生成可设；超限任务转人工，不静默删除。保留新评论起点、重启后显式继续 |
| 批量审核 | 展示评论和草稿，一次1～100条；可批准草稿、重新生成或跳过。只操作当前会话；不允许批准结果不明任务，批准后继续对应作品监听才发送 |
| 运行管理 | 每作品评论/成功/不明/失败统计、模型次数及平均耗时，流水线占用；网页可申请本机通知，页面关闭后不通知 |
| 知识库 | 最多30万字符；中文词片段/英文词检索，按评论选择最多6段；记录资料版本、片段ID/偏移/原文及完整资料hash，历史详情可追溯。不是向量检索或事实正确性保证 |
| 文档导入 | TXT/Markdown/DOCX/PDF文本，20MB、PDF最多200页、30万字符；独立Worker限时限内存，DOCX仅解析正文XML，PDF禁用eval。扫描PDF需另做OCR；旧DOC不支持 |
| OCR | 高精度模式增加阈值增强/稀疏文字识别，改善引擎选择，保留多版本与分歧标记；核对后采用，不能保证所有真实作品高准确率 |
| 完整备份 | 暂停所有任务后备份数据库与原始media，逐文件SHA256清单；恢复工具先校验，只写入不存在的新目录，拒绝覆盖。DPAPI凭据只供同Windows用户/机器解密 |
| 正式授权服务 | 可独立部署的服务端OAuth、AES-GCM令牌存储、设备凭证隔离及受限API代理；桌面仅保存加密设备凭证，应用Secret不下发 |
| 事件接入 | 官方原始字节验签、challenge、消息去重、7天元数据；事件只唤醒官方读取，保留分页补扫。未确认获批可用的通用新评论事件 |

## 使用顺序

1. 在账号管理新增账号并授权；当前用户的应用仍在申请/审批阶段，可先整理本地模型、作品与知识库。
2. 作品管理保存账号、模型、知识库、自动发送、检查间隔、每日额度和积压策略。未勾选自动发送只生成草稿。
3. 在工作台逐个启动作品，查看流水线与积压；需要修改配置时暂停全部，等待在途任务完成。
4. 需要审核时读取待审任务，逐条看评论和草稿，勾选后批准/重新生成/跳过；结果不明只走查询核验。
5. 设置中创建完整备份。校验：`node scripts/dev/restore-backup.mjs BACKUP_FOLDER`；恢复到新目录：`node scripts/dev/restore-backup.mjs BACKUP_FOLDER NEW_DATA_FOLDER`。关闭程序后再通过APP_DATA_DIR使用恢复目录，先保留原数据。完整备份不包含服务端vault和主密钥。

## 不能在本轮替用户完成的外部验收

- 用户确认应用“尚未申请或仍在审批”：实际权限、个人/企业及图文作品支持、官方评论读写未实测。
- 无生产HTTPS域名/证书与服务部署信息：授权服务源码和部署示例已提供，尚未部署上线。
- 评论事件能否订阅以获批应用后台为准；本次公开目录未确认通用新评论事件，不能承诺零漏读。
- 真实中文长视频、各云模型和本地模型效果需用用户自己的素材与连接实测，合成OCR样本不能代表整体准确率。
- 用户此前明确要求功能完成前不打包，本轮继续不执行stage/dist，不生成或验收新版EXE；旧0.3.0安装包仍不能代表当前源码。

## 已知限制

同一账号在不同设备上同时自动回复时，本地任务队列无法互相去重，建议一个主设备负责自动发送。动态分页、持续超载、离线、权限失效会影响发现完整性。通知依赖页面打开及系统授权。检索可能未召回答案；模型仍应在资料不足时说明无法确认。待审列表每次最多100条，持续积压需人工消化。恢复不支持跨用户解密原DPAPI Key；迁移到其他机器后需要重新填写模型和设备凭证。
