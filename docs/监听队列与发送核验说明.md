# 监听队列、分批扫描与发送核验（0.7.0）

## 日常操作

- **启动监听**：读取首页建立新的监听起点。已存在的评论按时间/基线跳过，取消旧会话未发送任务，不补发历史。
- **继续上次监听**：保留该账号/作品的监听起点、扫描游标和任务；用于暂停或重启后的恢复。程序重启后不会自动启动生成或发送。
- **核验未确认回复**：暂停监听后，在“监听进度与任务恢复”中点击。仅查询原评论下回复，不提交评论。后台也会对当前作品到期的核验任务做只读检查。
- **重置扫描进度（保留监听起点）**：分页游标失效或扫描异常时使用，再点击“继续上次监听”。这不会把暂停期间的新评论重新定义为历史。
- **重新安排生成**：生成任务被阻塞后，修复模型或知识资料，暂停监听，点击此按钮，再继续监听。发送结果不明的任务没有自动重新发送入口。

0.8.0 已增加同一官方账号的多作品公平调度，见[多作品监听说明](多作品监听说明.md)。仍由单后端进程管理同一数据库。切换账号/作品后不得挪用原账号任务；官方授权和真实图文接口支持仍需获批应用联调。

## 评论读取

启动仅预览官方评论首页（最多20条），不再要求先遍历全量历史。监听起点记录在 `monitor_sessions`，后面遇到更早的历史评论也不进入回复任务。

运行中每轮最多读取3页：总会检查首页，剩余预算续扫历史巡检游标。完成一轮巡检后再从头巡检。不根据一页的时间或置顶评论提前断言后面没有新评论，也不将小程序接口参数混用到移动/网站接口。

扫描检查点与已收集评论一同保存，异常时不推进未成功落盘的检查点。游标重复会停止；暂时连接失败、HTTP429等会持久化退避时间，最多连续失败5次后暂停。旧于监听起点的尾页历史只计数，不全量复制到回复队列。

这是**分批分页＋首页检查**，不是平台增量事件推送，也不是服务端快照。新评论插入、删除、置顶、推荐排序变化或极高流量会影响分页稳定性，不能保证零漏读；持续流量过高时需结合平台获批事件能力和实际额度进一步设计。官方评论文档部分已迁移，参数与行为需真实应用验证。

## 持久队列

SQLite `comment_tasks` 保存账号指纹、作品、监听会话、评论引用、阶段、状态、尝试次数及下次时间；同一作用域/评论只有一个工作流任务。

| 阶段 / 状态 | 行为 |
| --- | --- |
| generate / ready | 调用当前作品模型生成回复 |
| send / ready | 仅在自动发送开启、会话/账号/资料有效时进行发送前检查 |
| review | 草稿等人工确认，不自动提交 |
| retry_wait | 到达持久化时间后再试；重启不会清除正常等待时间 |
| blocked | 无权限、资料错误或重试耗尽等，需要处理后再安排 |
| verify | 只查询发送结果，不重发 |
| done / cancelled | 已完成，或新监听会话取消的旧未发送任务 |

模型连接失败、超时、HTTP408/429/5xx等暂时错误可重试，最多3次尝试；退避从15秒起指数增加，尊重可用的限流冷却时间。401/403/404、资料变化等不自动重试。重试模型请求可能产生额外模型调用费用。

进程退出中断的生成任务可在继续监听后恢复。中断在发送阶段的任务先进入人工确认/核验；若有已落盘的发送快照，则转换为核验。不会仅因任务还没标记完成就重新提交。

## 发送与核验

1. 发送前检查账号、作品、上下文指纹、每日上限和暂停状态。
2. 查询并记录原评论已有回复 ID；查询失败时不发送，读取阶段可退避重试。
3. 先落盘发送快照：账号、作品、评论、原文、时间、已有回复 ID 和尝试 ID，然后才调用官方发送接口。
4. 正常返回回复 ID 时标记已发送。超时或缺少 ID 时标记 `uncertain`，暂停后续发送，建立核验任务。
5. 核验只接受：当前授权作者、相同正文、新出现的回复 ID、在提交时间附近且不晚于检查时间的唯一回复。多个候选、缺作者/时间、缺快照或没有匹配，都保留结果不明。
6. 确认后更新原发送历史及回复 ID，不再提交；未确认最多自动查询3次，之后人工检查。手动点击核验只会重新查询。

该规则确认的是原评论下存在符合条件的新回复，不能证明一定由哪个客户端创建。查询为空不代表写入失败，平台可延迟展示或过滤结果，因此不会把“没查到”转换成自动重发。

发送前和核验的回复列表查询目前最多50页，每页20条；超过上限明确报错，不能悄悄以不完整结果确认。0.6.0及更早的结果不明记录没有发送快照时，无法套用本次自动核验，需要人工检查。

## 验证与边界

- `npm test`：队列唯一性、作用域隔离、退避、限流等待、恢复、扫描续页、重复游标、保守核验等。
- `npm run test:incremental`：1200条模拟历史、首页基线、每轮3页、跨进程续扫、历史不入队、重置不改起点。
- `npm run test:official-flow`：隔离授权/生成/发送、超时暂停、只读核验、历史更新、重启后确认保留，断言核验不增加发送次数。

所有平台请求为模拟验证，不宣称真实抖音账号、个人号权限、原图文作品或真实供应商已验收。本轮不打包。

官方依据：[评论列表](https://open.douyin.com/platform/resource/docs/openapi/interaction-management/comment-management-user/comment-list)、[原评论的回复列表](https://open.douyin.com/platform/resource/docs/openapi/interaction-management/comment-management-user/comment-reply-list)。
