# 正式授权服务与事件接入

服务源码位于 `src/broker/`，需单独部署，不能作为公开桌面客户端的一部分启动或分发密钥文件。客户端仅保存本设备凭证；抖音 Client Secret、access_token、refresh_token 留在服务端。令牌使用环境提供的32字节主密钥做AES-256-GCM加密，不依赖Windows，可部署在支持Node SQLite的Node 24.22或更新版本上。

## 部署步骤

1. 申请并获得抖音应用、实际可用的作品/评论权限及批准回调域名。用户目前表示“尚未申请或仍在审批”，所以真实联调暂不能完成。
2. 在服务机器运行 `node scripts/dev/configure-broker.mjs`，生成 `broker-data/broker.env`。脚本拒绝覆盖原配置，不输出秘密。填写获批的 Client Key、Secret、回调域名和对应scope；保存好加密主密钥，否则历史令牌无法解密。
3. 运行 `node --env-file=broker-data/broker.env src/broker/server.js`。服务仅监听127.0.0.1:4321，前面放HTTPS反向代理。示例见 `config/broker.nginx.conf.example`，配置证书、域名及系统服务自启动。不要记录OAuth回调查询参数或认证头。
4. `BROKER_DEVICES` 是设备名到随机凭证的JSON。每个安装设备配置不同的至少32字符凭证；只向该设备用户提供其凭证，不提供服务端配置文件。删除对应项并重启服务可取消设备访问。每个设备的账号槽位与令牌分别存储，设备不能读到其他设备的令牌。
5. 客户端“设置 → 正式授权服务”填写HTTPS域名和本设备凭证，密文保存到本机SQLite，重启后端生效。也可由管理员通过 `COMMENTPILOT_BROKER_URL` / `COMMENTPILOT_BROKER_TOKEN` 环境变量配置。客户端无需填写应用Secret。
6. 在账号管理里选择账号槽位，点击抖音授权，在浏览器完成服务端回调，再点“刷新服务端授权状态”。读取该账号官方作品，保存作品账号/模型/知识库绑定，最后启动监听。

服务端OAuth state与设备及账号槽位绑定、10分钟过期、一次性使用，回调不会携带令牌跳转到任意本机端口。服务重启导致未完成state失效时重新授权。服务只代理明确列出的作品/评论操作，不提供任意URL代理。正文请求限256KB、超时35秒，响应不包含令牌。桌面模型调用仍由本地工作台处理。

当前设备凭证由管理员发放，尚未接入商业用户注册、计费和组织权限体系。同一个抖音账号建议只有一个负责自动回复的主设备；不同设备并行授权同一账号时，各本地队列无法互相去重。

## 事件

服务端 `/webhooks/douyin` 按官方规则对原始字节计算SHA1(secret + body)，常量时间验签，校验client_key，响应challenge并去重保存有限元数据。事件不直接生成回复任务，只通知客户端唤醒一次有界的官方读取；评论正文、身份和去重仍以官方列表为准。元数据保留7天。

注意：本次核对的[官方事件目录](https://partner.open-douyin.com/docs/resource/zh-CN/dop/develop/webhooks/event-list)没有可确认适用于本场景的通用新评论事件。**不可把验签接入能力当成已获得评论事件订阅权限。**须以获批应用后台实际事件清单为准，未支持时继续分页补扫，动态分页不能保证零漏读。验签协议依据[官方Webhook说明](https://partner.open-douyin.com/docs/resource/zh-CN/dop/develop/webhooks/summarize)。

## 已验证与待实测

`node tests/integration/broker.mjs` 已在隔离本地服务、模拟抖音上验证设备隔离、一次性回调、服务端令牌加密、远程读写及不下发令牌。HTTPS证书、真实应用权限、实际回调与订阅尚未部署/联调，不能宣称已上线。服务备份需单独保留vault目录及加密主密钥，不能只备份桌面数据库。
