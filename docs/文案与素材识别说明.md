# 作品文案与素材识别（0.5.0）

本轮只完善功能，没有生成安装包。

## 如何使用

1. 在作品管理保存并选择具体作品。没有官方授权时，也可以先保存作品完整链接并整理本地素材。
2. 进入“文案与素材”，粘贴完整发布文案，点击“保存已核对文案”。从官方读取的 `title` 文案与人工补全文案分别保存，不会拿评论正文充当作品文案。
3. 导入属于这条作品的原图、GIF、WebP 动图、视频、音频或字幕。原文件由你提供，不通过浏览器抓取平台受限素材。
4. 默认只做本机 OCR 和字幕提取。需要理解无文字画面时选择支持图片输入的模型；需要识别口述时选择支持 `/audio/transcriptions` 的模型连接。两者都在“模型连接”中保存，可以与评论回复模型不同。
5. 选择视觉或语音模型后，需要勾选允许发送素材。选云端连接会上传图片/音频，并可能产生分段调用费用；默认本机 OCR 不上传。Ollama 仅支持已具备视觉能力的模型，不用它的文本聊天接口转写音频。语音服务需支持标准 multipart 转写请求及 JSON `text` 响应，不支持的服务会明确报错。
6. 点击“识别导入素材”，可查看进度和取消。完成后逐段查看来源、时间位置、OCR 置信度与遗漏提示，修正文案，再点击“采用核对后的识别结果”。未采用的结果不会进入模型回复背景。

## 已实现能力和边界

| 素材 | 当前处理 | 边界 |
| --- | --- | --- |
| 发布文案 | 官方 title 字段＋人工补全＋TXT 导入 | 官方字段可能不完整，TXT 识别结果仍需采用 |
| 多张图片 | 逐张中英文 OCR，保留来源与引擎结果 | 小字、花体、旋转、模糊或复杂背景可能识别错 |
| GIF / WebP 动图 | 根据解码页数抽帧，保留原帧序号和时间 | 超过预算只抽样，不承诺逐帧无遗漏 |
| 视频 | 完整 FFmpeg 解码，按时间抽帧 OCR，可选视觉理解 | 采样时间为近似值；不是完整逐帧理解或场景切换检测 |
| 视频字幕 | 第一条可用文本字幕轨；支持 SRT/VTT 导入 | 图像字幕依靠画面 OCR，不保证每条字幕都抽到 |
| 音频/视频口述 | 提取16kHz单声道 WAV，每60秒分段交给所选转写模型 | 需要合适的语音服务；可能有方言、专有名词和分段边界错误 |

本次最多导入20个文件；单文件512MB、每作品合计2GB；单段视频/音频最长2小时；一次最多120个画面，默认60。多个可视素材分配总抽帧预算。长视频自动增大抽帧间隔，以覆盖整体时长，间隔内的内容可能漏掉。字数超限会报错，不会悄悄截断后采用。

图片/视频帧完全相同时跳过重复画面，并提示仅保留首次出现时间。未启用语音、视觉模型或 OCR 置信度不足时会提示尚未识别的内容。**置信度不等于实际准确率**，不提供“任意长视频均高准确”的保证。

## 与自动回复的关系

模型依据本作品的知识库、发布文案、已核对补全文案和已采用识别内容回答。切换作品不混用资料；修改、停用或删除识别依据后，旧草稿的上下文 hash 会失效，需要重新生成后发送。新增素材会停用先前识别结果，重新识别或核对后采用；删除被引用素材也会停用。

素材解析期间不能启动评论监听。解析可取消；当前 OCR 步骤完成后停止，子进程解码和模型 HTTP 请求通过取消信号中止。错误、取消和程序中断的结果不会自动采用。程序重启后未完成任务标记中断，不会悄悄恢复云端调用。

## 保存、备份和验证

原文件位于 `data/media/<作品ID>`；SQLite 的 `media_assets` / `media_jobs` 保存来源、SHA256、任务、结构化时间轴和核对状态；素材模型调用也写入 `model_calls`，不保存 Key 或二进制请求内容。已采用文字通过原有作品内容版本及模型背景快照保存。识别中间图片、音频正常完成/取消后清理。

**数据库备份不包含原始媒体文件**。需要完整迁移时，在停止程序后同时备份 SQLite 和 `data/media` 目录。DPAPI 凭据仍受原 Windows 用户限制。

验证包括真实 FFmpeg 合成视频解码、字幕提取、音轨检测、动图抽帧、真实英文图片 OCR 的工作台导入/核对/作品隔离、模拟视觉/语音请求和取消/中断恢复。未将合成短视频测试声称为真实中文长视频准确率测试；真实用户素材、云端视觉和语音模型仍待实际联调。

工具依据：[Sharp 动图元信息](https://sharp.pixelplumbing.com/api-input/)、[FFmpeg 解码与字幕处理](https://www.ffmpeg.org/ffmpeg.html)。
