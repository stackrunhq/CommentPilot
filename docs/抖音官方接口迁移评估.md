# 抖音官方接口与当前浏览器方案评估

核查日期：2026-10-19。此文档记录公开资料与代码核对结果，不代表平台已授予本应用权限。当前发布版本仍为0.3.0浏览器版，尚未接入抖音官方授权和评论接口。

## 当前实现

Electron 桌面外壳，Node.js 本地 HTTP 后端；Playwright 控制 Chromium，保存登录资料，刷新页面、读取 DOM 和浏览器正常加载的评论列表响应，定位原评论后填写并点击发送。没有抖音开放平台 OAuth 授权或官方评论客户端。

SQLite 保存作品、知识库、评论、模型调用和发送历史；Windows DPAPI 加密模型 Key；通过模型 HTTP API 或 Ollama 生成回复；本地 Tesseract / Windows OCR 识别图片文字。模型接口是对应模型服务的接口，不等于抖音侧已获得官方授权。

代码依据：server.js、browser-comments.js、comment-network.js、providers.js、storage.js、desktop/main.cjs。

## 已核查的官方能力

- 普通评论管理文档：`item.comment`，需要申请权限和用户授权。评论列表 `GET /item/comment/list/`，回复列表 `GET /item/comment/reply/list/`，回复 `POST /item/comment/reply/`。回复仅限授权用户自己发布的视频。
- 企业号文档：`video.comment`，对应 `/video/comment/...`，明确要求授权用户为企业号。不能直接给个人号套用。
- 小程序视频评论能力：`ma.item.comment`，回复接口 `POST /api/apps/v1/item/reply_comment/`；需要在小程序控制台申请“视频评论数据”并完成对应用户授权。该路径文档明确标注图集目前不支持评论。
- 三条路径不能混用 scope、授权方式和作品 ID。旧文档页面部分内容存在迁移提示，实际开放范围、准入和配额必须以当前应用后台及平台答复核实。
- 目前不能保证此个人账号、应用主体及原图文作品可获得所需能力；也不能据此断言必须转企业号。未登录应用后台核实授权资格。

## 当前浏览器版的平台风险

已读取2026年2月13日更新、2月20日生效的[抖音用户服务协议](https://www.douyin.com/draft/douyin_agreement/douyin_agreement_user.html)。

条款5.1涉及自动化程序接入、收集或处理平台信息；5.3涉及未经书面许可获取或使用平台内容；4.6限制垃圾、过度营销及无关评论；7.1列举限制评论、限制账号乃至终止服务等处理。

根据这些条款，未获得相应授权的浏览器自动采集和自动回复存在明显平台协议风险。自己的账号、自己的作品、扫码登录、10秒间隔、每日限额、没有破解验证码，都不等于平台批准。现有程序不能对外承诺“抖音官方接入”或“零违规风险”。这属于平台规则风险判断，不将其直接等同于具体行为已经构成违法的法律结论。

调用官方接口也仍需遵守审核批准用途、频率、内容及数据使用规则；不能推导出可无限量自动回复或可任意将用户数据提供给第三方模型。当前云模型请求包含作者昵称、评论及背景，本地 Ollama 请求走本机服务；后续应核对授权和隐私要求并尽量减少非必要数据。

## 官方版改造路径

1. 核实应用类型、开发主体和可申请的评论 scope；明确原作品是视频还是图集，确认可支持的作品类型。
2. 建立官方 OAuth 授权、token 刷新、撤销与加密存储；不使用浏览器 Cookie 冒充 access_token。
3. 抽离评论通道，新增官方实现；按获批接口获取作品与评论 ID，不能把网页数字 ID 直接假定为官方加密 item_id。
4. 通过获批评论列表分页或已开通的事件能力发现新评论，遵守实际配额；不承诺沿用10秒检查或无延迟回调。
5. 复用现有作品知识库、模型连接、去重、基线和历史；用官方响应和查询核验发送结果，超时不盲目重发。
6. 面向他人分发时，将应用共享 client_secret 放在受控服务端；不把它硬编码进通用 EXE。根据应用类型确认授权回调与部署要求。
7. 对权限未通过、token 失效、类型不支持明确报错，不自动退回浏览器发送来绕开限制。

本轮仅完成调查和迁移评估，未修改生产配置、未启停监听、未声称官方 API 已接通。下一步所缺信息是应用后台的类型、权限申请状态和目标作品类型；不需要用户在聊天里提供密码、Cookie 或密钥。
