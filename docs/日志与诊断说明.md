# 日志、脱敏和问题诊断（0.6.0）

## 用户如何反馈问题

1. 记住问题发生时间，保留界面显示的“排查编号”。
2. 打开“设置 → 问题排查与脱敏诊断”。
3. 选择最近500/1000/2000条事件，点击“导出脱敏诊断报告”。
4. 浏览器下载 `CommentPilot-Diagnostics-时间.json`。先查看内容，再自行决定是否分享；程序不会自动上传。

这是一个独立 JSON 诊断报告，不是数据库备份或包含原始日志的 ZIP。不要用数据库备份替代它向外反馈问题。

## 能分析什么

- 已到达后端的操作顺序、开始/结束、结果、耗时、所属进程会话和 traceId。
- 配置保存、模型测试、作品选择、知识库操作、官方授权、素材上传/解析、启动/暂停/恢复监听等请求。
- 监听基线数量、读取数量、新评论/重复/历史/自己/时间不明数量。
- 模型调用和发送尝试状态、素材解析阶段，以及上游提供时的 HTTP/官方错误码。
- 官方应用是否配置、是否授权、监听/任务是否运行、非敏感模型协议与 Key 是否已配置。
- 重启前后仍在留存范围内的追踪。业务历史中的模型/发送记录也保留 traceId，可在本机关联查看。

操作按 traceId 分组，同一次请求内异步调用继承编号；每轮评论监听另建追踪。作品、评论、模型连接及任务使用引用代号，既能在同一报告中关联，也不直接公开原始 ID。每份导出使用新的随机盐，不应靠代号跨多份报告拼接用户身份。

错误分类是排查线索，不是自动根因结论。例如授权错误仍需核查应用资格、授权范围和令牌；模型错误仍需核查服务、型号、地域和余额。报告不会自动调用云端 AI 分析。

## 不包含什么

诊断导出使用固定字段白名单，不读取旧日志文件，不导出整个数据库，也不复制请求/响应对象。

- 不包含 API Key、OAuth access/refresh token、授权 code/state、Cookie 或请求头。
- 不包含评论/回复正文、知识库全文、作品完整文案、模型完整提示词/响应、素材文件或文件名。
- 不包含本机绝对路径、账号昵称、模型连接自定义名称、接口完整地址。
- 自定义模型名称以引用代号表示；供应商只保留已知枚举，Key 只保留“已配置”布尔值。
- 上游 requestId 使用引用代号，不能直接用于供应商查询原始请求；必要时需在本机进一步核查。

日志过滤同时覆盖已知凭据、常见 token、Authorization/Cookie、URL 查询参数、手机号、邮箱、身份证样式字符串和本机路径。JSON 解析失败使用固定错误，不回显原始正文片段。密钥保存/解密和官方令牌加载/刷新时登记秘密值用于过滤。

正则过滤不能保证识别任意自然语言中的全部隐私，因此诊断报告额外采用白名单，并彻底排除自由文本消息。第三方或运行时直接写入的 stdout/stderr 不等同于经过该白名单处理的诊断报告。

## 本机保存与保留

| 数据 | 位置和策略 |
| --- | --- |
| 新的结构化应用日志 | `data/logs/application.jsonl`，单文件约2MB，保留3份轮转备份 |
| 诊断事件 | SQLite `diagnostic_events`，保留30天，启动及每100次写入定期收敛至最近10000条（批次间可短暂多于上限） |
| 界面运行消息 | 最近100条；消息做敏感值过滤，按作品显示 |
| 评论、知识库、模型/回复历史 | 原 SQLite 业务表，仍按产品功能保存；不因诊断清理而删除 |
| 开发版 stdout/stderr、桌面 `backend.log` | 现有启动/运行时输出，可能包含第三方信息；不纳入诊断导出，旧文件不追溯重写 |

日志写入故障会标记诊断健康状态，不会触发模型或评论发送重试。意外退出后的发送仍按原逻辑标记结果不明，不能从日志推断应该自动重发。

安装版中的 `data` 对应用户 AppData 的实际数据目录。数据库备份包含原业务内容与加密凭据，并不等于脱敏文件。旧历史的内容不会被本轮自动改写或清除。

## 不能还原的边界

- 升级前未记录的操作、过期/被轮转的事件，无法补录。
- 没有发到后端的点击、离线或浏览器端异常，目前无法完整还原。
- 评论答错、OCR 识别错或知识库冲突，可能需要用户另外提供经核对的最小内容；报告本身不带业务全文。
- API 接受请求不代表平台最终展示；提交结果不明仍需人工核实。

## 代码与验证

- `src/security/redaction.js`：秘密值登记、文本/字段过滤、控制台输出过滤。
- `src/observability/logger.js`：异步操作上下文、固定字段日志、轮转与留存。
- `src/observability/diagnostics.js`：白名单导出、引用代号、操作分组与状态摘要。
- `src/ui/scripts/diagnostics.js`：设置页导出。
- `npm run test:diagnostics`：隔离后端/UI、隐私哨兵、错误编号、重启留存与文件下载；相关单元测试覆盖并发追踪、日志故障、轮转和过期清理。

本轮不打包，没有自动发送日志或诊断报告给任何人。
