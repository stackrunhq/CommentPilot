# 0.12.0 服务管理与验收

本轮补齐本机自部署版本的配置、运行、对话和维护流程。仍是单用户应用，不能当作已经通过生产验收的多人客服系统。

## 用户流程

1. 保存作品、已确认资料、模型连接。设置昵称、回复方式、每日发送上限与对话轮数，保存自动设置。
2. 打开浏览器扫码并确认自己的作品。点击“启动前检查”，查看作品、凭据、资料、账号确认和调用预算；连接是否真正可用仍应点击“测试当前模型”。测试会调用模型并计入次数。
3. 启动监听。界面提示单作品及页面读取范围，展示最近读取量、新增量和调用用量，不把可见评论数当作全量覆盖。
4. 在“运行与对话管理”展开对话查看评论、已生成回复、资料依据、累计轮数和停止原因。可暂停后转人工、关闭或恢复自动。恢复自动不补发已经跳过的任务。
5. 敏感关键词与超量积压转人工：先生成待审核草稿，再审核通过。通过后可显式发送；修改草稿会清除审核标志。人工接管允许显式发送，关闭对话禁止发送。所有发送仍受轮数、账号确认及每日限额约束。
6. 结果不明只允许在平台自行核对后记录人工确认，不会变成程序已核验成功，也不会因此重发。

## 设置中的服务策略

- 默认每日模型调用上限200次，已知Token预算200000，待处理阈值100条。失败调用也计数，评论生成和连接测试共用本机额度。媒体模型的独立调用未计入，不能用此数字代表全部模型开销。
- Token按服务返回用量统计；未返回用量的调用单独展示。在途请求可能使最终Token超出阈值。这不是精确金额或供应商账单，不提供跨设备共同预算。
- 默认人工审核关键词为投诉、退款、法律、赔偿、身份证、银行卡，可自行修改。这是关键词筛选，不能保证识别所有高风险内容，也不是内容正确性的证明。
- 同作者、同评论文本、相同回复一小时内重复提交会被拦截。该规则只供本机使用，昵称相同可能导致保守拦截。

## 数据维护

- 过期清理先备份，再删除超出保留期限的模型调用明细和业务事件。默认90天，保留评论与发送记录、防重标识和轮数，不自动清空知识库与媒体。
- “每日自动完整备份并清理”默认关闭。启用后只在程序运行、监听暂停且没有任务时执行，最多每天尝试一次；持续运行监听期间会延后。备份尚不自动轮换，请定期管理磁盘空间。
- 完整备份包含数据库和媒体，恢复前校验清单和数据库完整性。界面只能恢复到新目录，不覆盖当前目录、不自动切换当前实例。关闭程序后以恢复目录部署；浏览器登录状态不在完整备份内，需要重新登录。
- 可导出当前作品及其评论、回复和调用明细。文件包含业务正文，需自行保管；不包含API Key或登录凭据。
- “清除当前作品文本”要求输入作品ID，并先完整备份，清除评论、回复、调用正文及提取文本，关闭其对话、解除知识库关联并关闭浏览器。保留去重标识、轮数和调用用量。原媒体、共享知识库和旧备份仍保留，所以此操作不等于彻底删除所有个人数据。
- API Key使用已有Windows DPAPI；换机器或Windows用户时需重新配置。

## 本机运行保护

同一数据目录通过进程锁拒绝第二个活动后端，降低同机重复发送风险。锁损坏会拒绝启动，不会擅自结束其他程序。不同目录、不同电脑之间尚无分布式主设备选举或发送锁，仍应只由一台设备负责同一账号自动发送。

## 已验证与未完成

新增服务管理隔离测试覆盖：启动检查、两步审核、持久化接管、人工确认、预算拦截、备份及独立恢复、文本导出与清除后预算/防重保留、界面无脚本异常。单元测试85项通过；浏览器三轮回复仍使用合成页面验证。

以下不能标记为完成：真实抖音评论与楼中楼联调、全量分页和高评论量覆盖、个人浏览器多作品并行、跨设备去重、真实模型费用核对、多人账号/角色权限、不可篡改审计、独立告警服务、自动签名更新与回滚、实际签名安装包、生产授权部署。这些需要进一步实现或真实环境验收；目前不打包。现有管理审计属于本机操作记录，不具备身份认证或防篡改保证。

## 0.13.0 更新

审核现在绑定草稿版本，旧审批需重新批准。追问只使用直接回复链的历史，其他参与者转人工；有账号ID时优先校验ID，缺失时昵称仍可能同名。回复关系待加载将重查，连续12次未解决转人工。轮数依旧按一级评论累计。

自动维护的下一次执行时间已持久化，失败或中断后不在重启时立即重复；可手动备份检查。工作台显示最近200条，完整记录在历史页面分页查看。三万条合成数据已验证增量写入及分页性能，后台仍持有全量记录，不能据此保证高评论量或长期运行稳定性。
