# 多作品监听（0.8.0）

**0.9.0更新**：已拆分采集/生成/发送流水线，支持多账号、可配云模型并发、积压转人工和批量审核。下文保留0.8行为作为历史说明，当前使用请优先查看[功能完善与验收清单](功能完善与验收清单.md)。

在作品管理中保存每个作品的模型连接、知识库、背景、检查间隔和自动发送设置，然后在工作台“多作品后台监听”逐个点击“启动新监听”。仅支持当前官方授权账号，最多同时20个作品。

- **启动新监听**：以当前时间建立新会话，首页已有评论及此前未发送任务不补发。
- **继续上次监听**：恢复该账号、该作品保存的起点、扫描游标和未完成任务。重启程序不会自行开始发送。
- **暂停该作品**只停止该作品；**暂停全部作品**停止所有监听。已发出的请求可能仍完成，暂停不会撤销已发布回复。
- 修改作品配置、模型、知识库或切换工作台当前作品前先暂停全部监听。运行时使用各作品独立的配置快照，后台调度不改变当前工作台选中作品。可在作品历史中按作品查看评论和调用/发送详情。

## 评论高峰如何处理

每个作品一轮最多读取3页，然后执行最多2个队列步骤（生成或发送），轮流让出机会，避免单个作品先清空全部任务。不同作品的评论、会话、模型连接、知识库及发送快照分别绑定。模型并发上限1，发送并发上限1，整个账号的提交尝试至少间隔3秒；官方429冷却由账号共用。限制是本机调度策略，不代表平台批准的额度，仍须根据实际应用额度调整。

每作品使用自己保存的每日上限（1～200），此外当前账号每天最多200条提交，按上海日期计算。成功、发送中、结果不明均占额度，结果不明不会盲目重发。达到上限会阻塞该任务并暂停该作品，需检查队列并在合适时间人工继续。

界面显示待处理积压数量、最久等待时间；积压达到100条或等待5分钟时提示。仅生成草稿的人工待审任务不计入自动处理积压。队列保存在SQLite，不自动删除或过期丢弃任务；持续积压会增长本机数据，应由用户调整处理策略。

检查间隔是每作品一轮结束后的最短等待时间，默认10秒；多个作品、慢模型、重试和平台限流都可能进一步延迟。当前模型调用与读取共用串行执行窗口，慢模型会延迟其他作品扫描。**这不是每条评论10秒内必定回复的保证，也不是全量无漏的评论事件流。**动态分页位置移动、持续高流量、长时间离线都可能漏读；获批事件订阅、读取/生成流水线解耦及可配置并发仍属后续增强。

发送结果不明时暂停该作品的发送，后台只读核验按作品轮流执行，暂停及重启后仍可核验，不会自动重新POST。任务与核验规则见[监听队列与发送核验说明](监听队列与发送核验说明.md)。

## 验证边界

`npm run test:multiwork` 使用隔离进程、数据库与模拟官方/模型接口，验证两个作品不同模型和知识库、评论负载不均时的公平处理、积压、暂停、重启后继续和不重复发送。另有调度互斥单元测试。没有使用真实抖音权限或云模型联调；本轮不打包。
